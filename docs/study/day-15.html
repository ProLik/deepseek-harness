Promise 与流的观察时机不同

Promise<T> 只在结束时给 T。AsyncIterable<Chunk> 允许消费者每到一个 chunk 就处理一次，因此 UI 可增量显示，Session 也可记录原始响应。

for await...of 会等待下一个异步值，但不会阻塞整个 Node 进程。

具体例子

模型返回三段文本时，循环会观察三次 assistant/chunk，最后再形成 assistant/message。

原始 chunk 与最终消息各有用途

chunk 保留流式到达顺序和 provider 过程信息；最终 message 是后续模型历史使用的完整助手输出。

只保存最终文本会丢失推理、工具增量或调试事实；只保存 chunk 会让每个消费者都重复组装。

具体例子

SessionEventMap 同时有 assistant/chunk 与 assistant/message，分别服务事实记录和派生历史。

取消需要沿调用链传播

拥有 Agent 操作生命周期的一层创建 AbortController，将 signal 传给 prompt、LLM 和 tools。下游观察 signal，不自行决定全局取消。

abort 不是普通错误，也不自动完成 cleanup。调用方还要记录结束原因并 dispose 在途资源。

具体例子

用户 cancel 后，adapter 应停止流；Agent 仍需追加正确的 step/turn 结束事实。
