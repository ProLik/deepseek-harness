一、从零开始的概念讲义

先建立词义和因果关系，再阅读本页后面的源码卡片。下面每一节都要能用自己的话复述。

Profile 不是另一个可执行文件

所有受支持 Node 应用都通过 dsh 启动。web、headless、sdk、sdk-minimal、acp 的差别主要来自 profile 选择的 bundle 和 patch，而不是各自拥有产品 bin。

这使启动、环境、关闭和错误处理保持统一，应用差异留在可检查的配置组合中。

具体例子

dsh --profile web 与 dsh --profile headless 都先进入 apps/cli/src/bin.ts，再由同一个 runProfile 组合不同层。

Bundle 提供可复用底座

一个 profile manifest 声明按顺序使用哪些 bundle。每个 bundle 的 cordis.patch.yml 可以插入 Definition、Provider、Consumer 和基础设施插件。

Profile 自身 patch 只表达该应用需要的差异。这样 sdk-minimal 不必复制 base 的每一行。

具体例子

base bundle 建立常用 Agent spine；web-app 叠加服务器、API 和客户端相关插件。

后层覆盖前层，但仍要引用有效条目

composeEntries 依次处理每组 patch。后层可以按 id 修改前层，但不能假装修改一个从未存在的条目。

层顺序同时表达所有权：bundle 是发行默认值，profile 是应用差异，DSH_HOME 是本机用户偏好，--patch 是本次调用覆盖。

优先级不是“哪个文件更重要”，而是明确的应用顺序。
