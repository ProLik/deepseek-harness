runProfile 先组合 profile，再准备 shutdown、readiness、环境快照和 cmdline 服务，随后调用 boot。配置树插件全部挂载并完成 host setup 后，launcher 才 commit ready。

服务必须在消费者挂载前提供

环境快照、cmdline、shutdown 和 appReady 属于 launcher 拥有的服务。boot 的 hostCtx 回调在配置条目挂载前安装它们。

后续插件只依赖服务定义读取一致快照，不直接读一部分旧环境、一部分新环境。

关闭和启动同样重要

SIGINT、SIGTERM 或应用主动退出会要求 shutdown。shutdown 最终 dispose root fiber，使 effects、事件监听和 provider 依生命周期撤销。

AbortController 用于通知仍在启动或运行的工作；dispose 则回收已经挂载的资源。二者解决的时间点不同。

小白最容易卡住的地方

误区：Node 进程还在就是 ready

异步挂载可能尚未完成；必须使用 launcher readiness 事实。

误区：发生错误直接 process.exit 就够了

已挂载资源需要先通过生命周期 dispose，退出码由 shutdown 策略拥有。

误区：AbortSignal 会自动释放所有资源

它只传递取消；监听、服务、进程等仍需 disposer/fiber 生命周期回收。
