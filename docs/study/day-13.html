一、从零开始的概念讲义

事件让插件在不互相导入时协作

Definition 在 Cordis Events interface 声明事件名、参数和 mode。生产者通过 ctx.emit/waterfall 触发，消费者用 ctx.on 注册。

双方依赖事件定义而不是彼此实现，listener 也随 Context 生命周期撤销。

具体例子

system-prompt/change 通知缓存或消费者重新组装，而注册者无需知道有哪些监听者。

Waterfall 是嵌套调用链

每个 listener 接收 next。它可以在 await next() 前处理输入，也可以在后处理返回值。调用顺序类似 A前→B前→C→B后→A后。

最终返回值由完整链共同产生，因此仓库规定 listener 必须调用 next() 委托。

具体例子

system-prompt/assemble 允许多个插件协作修改 assembly；某个 listener 忘记 next 会让后面的 tools/context 贡献消失。

短路不是普通 return

普通 async 函数 return 只结束自己；waterfall listener 不调用 next 会改变整个扩展链。只有事件定义明确允许拥有短路语义时才能这样做。

Code review 时看到 waterfall listener，应先检查每条分支是否调用或返回 next，而不是只看主要分支。

具体例子

提前返回 undefined 在 waterfall 中不是“什么都不改”，而可能是“阻止所有后续 listener”。

六、常见误区与自测

小白最容易卡住的地方

误区：next 只是可选回调

在 waterfall 语义中，委托是扩展共存的必要条件。

误区：return 当前值等于“我不修改”

它可能直接结束链；不修改也应调用 next。

误区：事件没有依赖顺序

Waterfall 有明确嵌套顺序，scope 和注册顺序会影响参与者。

1. emit 与 waterfall 的核心差异？

waterfall 的链式返回值是权威结果，emit 主要广播。
