一、从零开始的概念讲义

先建立词义和因果关系，再阅读本页后面的源码卡片。下面每一节都要能用自己的话复述。

先把 YAML 翻译成普通数据

YAML 看起来和 JSON 不同，但仍主要表达数组、对象、字符串、数字和布尔值。短横线开始一个数组项，缩进表示对象属于哪个父字段。

阅读时可以在纸上画括号：同一缩进属于同一对象，更深缩进属于上一个字段。不要靠颜色猜层级。

具体例子

insert 下的多个 “- id:” 是 patch 要插入的多个插件行；每行的 name 和 config 属于该 id。

id、name、config 分工

name 选择要挂载的插件模块。id 标识配置树中的这一行，后续 patch 可以精确修改或禁用它。config 只提供该插件声明的部署参数。

稳定 id 是配置组合的连接点。若后层引用不存在的 id，系统应尽早报错，而不是静默忽略配置。

具体例子

同一个 provider package 可以被不同 id 挂载多次；id 表示配置实例，name 表示插件实现。

!!js 是受限制的配置表达式

大多数配置应保持普通 YAML 数据。仓库允许插件 config 和 entry disabled 使用 !!js，让 Loader 在受控位置表达条件或引用。

单感叹号 !js 不是仓库接受的标签。你今天只需要能识别 !!js，并知道其他 metadata 必须保持字面值。

平台条件可能决定某个 shell provider 是否 disabled，但插件名和 id 仍是普通字符串。

六、常见误区与自测

小白最容易卡住的地方

误区：缩进只是排版

YAML 缩进决定数据层级；改变空格可能改变 config 的拥有者。

误区：id 就是 npm 包名

id 标识配置实例，name 才指向插件模块。

误区：所有字段都能写 !!js

仓库只允许受控位置；其他 metadata 保持字面值。
