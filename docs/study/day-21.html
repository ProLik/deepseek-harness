静态类型到不了模型输出那一端

TypeScript 编译时并不知道模型最终生成的 arguments JSON。即使 ToolDefinition 在源码里类型正确，运行时仍可能收到缺字段、字符串冒充数字或额外结构。

因此工具执行前必须按 schema 验证，不能用 as 强制相信。

具体例子

defineTool<{count:number}> 不会让模型自动产出 number；validateArgs 才能在运行时拒绝 {"count":"many"}。

Schema spec 同时服务模型和实现

仓库的 ParameterSchemaSpec 是适合 TypeScript 作者编写的声明。转换函数生成标准 JSON Schema 给模型，InferArgs 则给工具实现静态参数类型。

同一来源减少“模型看到的 schema”和“实现假设的类型”漂移。

具体例子

属性 required:true 会进入 JSON Schema required 数组，同时让推导 args 字段非可选。

验证错误要带路径

只返回 false 无法告诉模型或开发者哪个嵌套字段错。validateArgs 返回错误列表，包含 value.path 等定位。

ToolRuntime 将验证失败变成规范化 ToolFailure，工具实现不会接触无效 args。
