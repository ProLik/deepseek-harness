静态导入和动态导入解决不同问题

静态 import 适合每次执行都需要的依赖，例如 readFileSync 和 parseDshArgs。动态 await import() 适合只有某个 mode 才需要的模块。

bin.ts 先解析 mode，再动态加载 profile-boot、plugin 或 dump-config。这样顶层分发清楚，也避免不同模式不必要地加载全部启动代码。

模块位置不等于当前工作目录

process.cwd() 是用户从哪里启动命令，可以变化。import.meta.url 是当前模块文件位置，适合定位相邻 package.json。

readVersion 使用 new URL("../package.json", import.meta.url)，所以无论用户在哪个目录执行 dsh，都能找到 CLI 自己的 manifest。

小白最容易卡住的地方

误区：动态 import 与静态 import 返回同样的值

动态 import 返回 Promise，需要 await 后得到模块命名空间。

误区：process.cwd() 就是源码文件目录

cwd 属于进程调用位置；模块文件位置由 import.meta.url 表达。

误区：default 分支说明未知 mode 是正常输入

这里 default 主要承担穷尽保护；合法 mode 应已由解析器限定。
