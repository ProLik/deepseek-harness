DeepSeek Harness 30 天源码学习课程

不要求你预先掌握 Node.js、TypeScript、依赖注入或 LLM。课程从当前源码里的最小例子出发，每天只增加一层复杂度，最后能独立拆解整个能力族。

离线阅读承诺：课程所需概念、当前源码摘录、命令说明、项目步骤和参考材料均已写入每天的 HTML 页面。无需联网，也无需另开编辑器搜索仓库；源码链接仅供学完后的可选延伸阅读。

怎样使用这套课程

每一天是一章完整教材，建议拆成 2–3 次、总计 2–3.5 小时完成。依次完成“概念讲义 → 术语练习 → 四站源码精读 → 运行跟踪 → 命令实验 → 项目实战 → 间隔复习”，不要提前通读大文件。第一次只读成功路径；取消、并发、恢复和平台分支留到课程指定的日子。看不懂时先回答三个问题：输入是什么、输出是什么、谁使用它。

版本说明：课程按当前 checkout 的 0.1.2-alpha.2 与 51 个 package group 编写。每次运行课程生成器都会重新核对 120 组目标符号，并从当前源码生成行号和上下文摘录；源码变化后应重新生成页面。所有核心练习不需要 API Key。

先备知识路线：不用先学完，再来看项目

你列出的知识点都可以在这个仓库里逐步学。课程采用“遇到真实问题时再补概念”的顺序：先看一个很小的项目例子，再学习够用的语法，最后回到源码解释它。每一行只要求达到“能继续读下一段”的程度，不要求第一遍精通。

你暂时不了解的知识从哪一天开始先看哪个项目证据这一阶段只需达到
终端、Node.js、pnpm第 1–2 天package.json 的 scripts 与 apps/cli/src/bin.ts能从一条命令追到实际执行的 TypeScript 文件
TypeScript 类型系统、ESM第 3–4 天Agent 接口、ReactLoopAgent、CLI 动态 import能读函数签名、判别联合、import/export；复杂泛型先跳过
测试与 mock第 5 天Session 的最小测试与 MockAdapter会先找断言，再定位动作和最小依赖
YAML、Profile、Bundle第 6–9 天cordis.patch.yml、loadProfile()、boot()能解释配置层怎样按 id 合成并变成插件树
依赖注入、Service、生命周期第 10–12 天Cordis Context、LlmRuntime、可撤销注册能区分能力定义、提供者、消费者，并找到 disposer
事件驱动、waterfall第 13 天system-prompt/assemble 与 invariant listener能区分广播与合作链，并知道 listener 何时必须调用 next()
异步流、LLM 工具调用第 14–16、20–25 天StreamChunk、step()、ToolRuntime.execute()能画出一次模型流和一次工具调用的输入输出
事件溯源、JSONL、SQLite第 17–19、26–27 天SessionEventMap、deriveMessages()、两个持久化 provider能说明日志为何是事实来源，以及投影如何重建

Web、RPC、SDK、协议适配第 28–29 天Web bundle、Session Controller、SDK/ACP/Webhook能追踪外部请求怎样复用同一 Agent 与 Session

每次只完成一个闭环

先用 10 分钟读概念，再按页面顺序阅读 4 个源码站点中的嵌入卡片；最后执行命令并完成一个小项目。课程正文不要求打开其他文件。

看不懂时不要硬撑

先记录“调用者、输入、输出、可观察事件”四项。某个泛型或 helper 超过 15 分钟仍不懂，就写下名字继续成功路径，后面的运行图会补上上下文。

一章可以拆成三次

第一次完成概念和前两站，第二次完成后两站与运行跟踪，第三次完成命令实验和项目。页面会在本机保存勾选进度；间隔一天复述不出来时，只重读答错的源码站点。

全仓 51 个能力组地图

课程深读核心脊柱，其余 group 用第 30 天的 Definition → Provider → Consumer → Bundle → Test 方法继续。下面是当前 checkout 的完整分组，不把 experimental 当正式产品入口。

核心与组装：优先读

决定应用如何启动、模型请求如何执行、事实如何保存。

boot bundle context core llm session compaction preset

外部入口：核心后读

把同一 Agent/Session 投影到浏览器、RPC、SDK 和协议客户端。

acp api client host sdk typert webhook

执行与工具能力：按需读

通常能找到完整 Definition / Provider / Consumer 三角色。

attachment code-runtime e2b fs lsp mcp sandbox shell skill spill storage subagent subprocess terminal web workflow workspace

交互与运行治理：主干后读

通过事件、Prompt、Tool 或 projection 扩展循环。

credentials extensions feedback goal guard identity interaction jobs plan runtime-diagnostics schedule session-query settings todo

集成与支撑：最后读

帮助组合、测试与接入，不是核心 turn 的所有者。

examples hooks test-support util

实验区：有兴趣再读

原型不属于官方发布面，不用它推断稳定架构。

experimental
