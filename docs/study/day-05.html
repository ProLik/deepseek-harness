测试标题先告诉你要证明什么

阅读测试时先看 describe/it 标题和最后的 expect。标题应该描述行为，expect 定义可观察结果。中间的 fixture 只在解释该结果所必需时才深入。

不要把测试当作逐行实现说明。它刻意省略生产配置，只保留触发行为所需的最小组合。

具体例子

“derives message history from the event log”直接给出输入来源 event log 和输出 message history。

Arrange/Act/Assert 帮你切开长测试

Arrange 可能包括 new Session、挂插件和准备 mock 输出。Act 通常是一到两行，例如 append 或 followup。Assert 使用 expect 检查消息、事件、状态或错误。

同一测试如果包含多个动作，先找到导致目标断言变化的那一个；清理和等待不一定属于 Act。

具体例子

new Session 是 Arrange；append 是 Act；expect(session.deriveMessages()) 是 Assert。

Mock 不是随便返回一个假值

MockAdapter 必须遵守真实 adapter 的接口和时序：接收相同请求、支持流式 chunk、响应取消。差别只在于输出由测试控制，不访问网络。

可靠 mock 让 Agent Loop 测试聚焦调度和日志语义，而 provider 自己的翻译与 HTTP 行为由 provider 测试负责。

具体例子

预设两个 chunk 能稳定验证 assistant/chunk 的顺序，而真实网络流无法保证测试每次相同。

六、常见误区与自测

小白最容易卡住的地方

误区：测试通过就证明整个仓库都正确

聚焦测试只证明被覆盖的行为和环境。报告时只能声称运行过的范围。

误区：skipped 表示失败

使用 -t 时不匹配的 case 会跳过；关键是匹配 case 的结果和退出码。

误区：mock 越简单越好

mock 必须保留消费者依赖的接口、时序和错误语义，否则测试会证明错误的系统。
