先理解四层目录

第一层是整个 deepseek-harness 仓库。第二层是 apps、packages、docs、scripts 等用途目录。第三层 packages/<group> 按领域聚合能力。第四层 packages/<group>/<package> 才通常拥有 package.json、src 和 tests。

目录嵌套只表示代码归属，不直接表示运行顺序。实际运行顺序来自 profile 配置、插件依赖和函数调用。你今天只建立地图，不尝试解释所有箭头。

具体例子

packages/core/session 表示 core 领域里的 session package；packages/session/session-persistence 表示 session 扩展领域里的 persistence package。两者名字相近，但职责不同。

README、manifest、src、tests 分别回答什么

README 告诉读者这个目录负责什么以及从哪里继续。package.json 告诉工具包名、版本、依赖、导出和脚本。src 保存实现，tests 用最小输入证明可观察行为。

初学者容易直接从最长的 src/index.ts 开始读。更稳的顺序是 README → package.json → 最短测试 → 公共类型 → 实现。页面中的源码卡片已经按这个顺序排列，让每一步都有问题要回答。

六、常见误区与自测

小白最容易卡住的地方

误区：文件越长越重要，所以先读最长的 index.ts

长度只表示实现复杂度。初学者应先用 README 和测试确定问题，再进入相关符号。

误区：packages 下的目录顺序就是程序启动顺序

目录只组织所有权；启动顺序由 profile patch、inject 依赖和插件挂载决定。

误区：笔记必须第一次就完全正确

第一版笔记允许标记未知。后续用测试和调用关系修正，比凭印象填满更可靠。

先在纸上回答，再展开答案。答错不是失败；回到本页对应源码站的卡片找证据。

1. group 和 package 有何区别？

group 按领域组织多个 package；package 有自己的 package.json，是依赖和发布单元。

2. 为什么不按字母顺序读？

目录顺序不表示执行依赖，应沿入口、数据和事件流阅读。
