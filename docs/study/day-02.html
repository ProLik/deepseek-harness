一、从零开始的概念讲义

先建立词义和因果关系，再阅读本页后面的源码卡片。下面每一节都要能用自己的话复述。

Node 与 pnpm 不做同一件事

Node.js 负责执行程序。pnpm 负责准备依赖并选择要执行的 script。运行 pnpm dsh 时，pnpm 先读根 package.json，然后启动 scripts.dsh 指定的 Node 命令。

因此故障也要分层判断：找不到 script 是 pnpm/manifest 问题；Node 版本不符合是运行环境问题；进入 bin.ts 后报参数错误才是 CLI 逻辑。

具体例子

pnpm dsh --version 可以拆成：pnpm 找 dsh script → Node 加载 tsx/esm → 执行 apps/cli/src/bin.ts → parseDshArgs 处理 --version。

为什么源码能直接写 .ts

Node 默认不能在所有受支持版本上直接执行本仓库的 TypeScript。根 script 使用 node --import tsx/esm 安装 ESM 加载钩子，让 import 的 .ts 文件在运行时被转换。

这条路径仍遵守 ESM 规则。模块必须使用 import/export，不能假设 CommonJS 的 require 或 __dirname 存在。

具体例子

关键不是背 tsx，而是能在 script 中指出“谁让 Node 认识 .ts”。

workspace 依赖让本地 package 组成系统

apps/cli 不复制 app-boot 的源码，而是在自己的 package.json 中声明 workspace 依赖并通过包名导入。TypeScript 检查时解析 src，构建和发布时则使用声明的 exports。

阅读跨 package import 时，先用本页 package.json 卡片确认 exports，再读对应的 src 入口卡片。不要用相似文件名猜。
